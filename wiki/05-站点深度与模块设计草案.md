## 第一轮：纵向隐喻与色彩系统（海面 → 海底）

### 1.1 叙事

- **浪前（近海面）**：空气与光更足，背景偏 **浅蓝 / 薄青**（仍属深色 UI，但不是纯 `#131313` 一块死黑）。
- **下潜**：随页面 **向下滚动**，背景在 **色相与明度上连续下沉**（可辅以轻微饱和度衰减），直到 **深海区**：**深蓝近黑**（与当前 `--background` / `--brand-navy` 家族衔接）。
- **寓意**：从「浪前车库」的开放入口，进入证据、人物与社群的 **水压递增区**；信息密度可随深度略升，但 **对比度与可读性** 必须全程合格（Harmless Engineering）。

### 1.2 工程落点（后续开发时遵守）

| 手段 | 用途 | 风险 |
|------|------|------|
| **CSS 变量链** | 定义 `--depth-surface`（浅）、`--depth-mid`、`--depth-abyss`（深），按 **区块或滚动进度** 插值 | 与 **全局 WebGL 底床** 叠色时需测合成，避免发灰或发粉 |
| **`color-mix()` / 长渐变** | `body` 或主内容包装层 **极缓** 的 `linear-gradient(180deg, …)` | 须与 `GlowRiver`、首屏网格 **同读一套深度令牌**，避免两套叙事打架 |
| **ScrollTrigger scrub** | 将 `--depth-t`（0→1）绑定滚动，驱动上述变量 | 与现有 `--wave-*`、相机变量独立命名，避免 GSAP 串改 |

### 1.3 与现有首屏的关系

- 首屏可保持 **略浅** 的「海面感」；**#proof 及以下** 逐步沉入深蓝。  
- **首屏 WebGL** 形态以代码为准（拓扑网格海等）；色彩下沉主要由 **HTML/CSS 层** 承担，WebGL 仅 **降低存在感**（已有 `--wave-opacity` 等），避免双主导。

## 第二轮：官网「有多深」— 信息架构（IA）草图

以下为 **单页加长** 与 **未来子路由** 可并存的结构；深度用 **纵向区块顺序** 表达（非必须一页到底，但叙事连续）。

| 顺序（浅 → 深） | 区块（工作名） | 对应产品叙事 | 备注 |
|------------------|----------------|----------------|------|
| 0 | **Manifesto / Hook** | 浪前、品牌重击 | 已实现骨架 + 底床 |
| 1 | **The Proof（证据）** | 方法论、内容承诺 | 已实现骨架，待接真实列表 |
| 2 | **Social Matrix（社交矩阵）** | 一键抵达各阵地 | **新模块**，见第三节 |
| 3 | **Founder Media（创业者采访）** | 人物与故事 | **新模块**，视频 B 站 + 文章外链微信 |
| 4 | **Community & Contact（社群与联系）** | 入群、找人 | 与现有 **The Call** 合并或上下级；含助手二维码 + 其它渠道 |
| 5 | **Footer** | 版权、次要链 | 可极克制 |

**「有多大」的实用定义**：

- **MVP 首页纵向**：约 **4～6 屏有效内容高度**（视文案与卡片数量），避免为深而深。  
- **子页面**：单篇采访、单篇微信跳转说明页等 **另起路由**，不在首屏堆完全文。  
- **深度令牌**：全站建议 **0～1 单一进度** 映射到背景插值；子路由进入时可 **重置或继承** `depth`（实现阶段再定）。

## 第三轮：三大模块 — 需求与界面约束

### 3.1 社交媒体矩阵（Social Matrix）

- **目标**：用户 **一眼扫到** 全渠道，**一次点击** 跳转站外。  
- **形态建议**：  
  - **Linear 感**：一行或两行 **等宽卡片** / **图标 + 短标签**，`hairline` 边框、hover 仅 **边框或前景微亮**，无大块色块跳动。  
  - 渠道示例（以实际运营为准）：B 站、微信、微博、小红书、Twitter/X、LinkedIn 等。  
- **工程**：外链 `rel="noopener noreferrer"`；图标 **SVG** 或 **单色**；考虑国内加载 **不依赖外网 icon CDN**。  
- **A11y**：每个链接 **可聚焦**、`aria-label` 写明平台名。

### 3.2 创业者采访（Founder Media）

**（a）视频类**

- **内置 B 站 iframe**：使用官方 embed（`player.bilibili.com`），**懒加载**（`loading="lazy"` + 进入视口才挂载 iframe），减少首屏与滚动 TBT。  
- **版式**：16:9 容器 + `aspect-ratio`；标题 + 人物一行 meta；与 Linear 一致 **大留白 + 细分割线**。  
- **合规**：遵守 B 站外链与品牌使用规范；若需备案或隐私说明，在模块下 **一行小字**。

**（b）文章类**

- **跳转微信公众号**：卡片展示标题、摘要、日期；点击 **新开页** 到微信文章 URL（若仅有二维码则 **次选**，优先可点击 URL）。  
- **工程**：外链同 3.1；若无法直链，采用 **「复制链接」+ 二维码** 双通道。

**分类展示**：Tab 或 **两段列表**（「视频」「文章」）二选一；默认 **视频在上** 或按运营权重配置。

### 3.3 社群与联系方式（Community & Contact）

**（a）小助手二维码**

- **目标**：进入「浪前」社群。  
- **形态**：与 Linear 类似 **单卡**：左侧文案 + 右侧 **固定尺寸二维码**（`220×220` 左右），浅 `hairline` 框。  
- **工程**：图片 **Next/Image** 或静态 `public/`；提供 **简短说明**（扫码后步骤）。

**（b）联系我们**

- 与现有 **邮箱、微信复制、合作说明** 合并为 **同一深度区**，避免分散在多个「Call」变体。  
- **不**在滚动中改正文 `opacity`（项目红线）。

## 第四轮：Linear 式「高级感」— 可执行的设计语言（非照抄）

参考 [Linear](https://linear.app/) 的 **气质**（非像素级复刻）：**暗色、高信噪、极少装饰、动效克制、边框即层次**。

| 维度 | 做法 |
|------|------|
| **背景** | 深色底 + **极弱**纵向渐变或纯色阶变化；**不出现**大块高饱和装饰渐变 |
| **边框** | 统一 `hairline`；hover 时 **边框或前景** 略亮 1 级，非整卡发光 |
| **圆角** | **小圆角或直角** 二选一全站统一；避免「卡片圆角 + 巨型圆按钮」混用 |
| **字阶** | 英文标签 **全大写 + 宽字距**；中文正文 **略大行高**；标题 **流体 clamp** 已有则延续 |
| **动效** | **Scroll-linked** 为主；进入视口 **短促** `fade/slide`；禁止正文 `opacity` scrub |
| **密度** | 列表与卡片 **宁可少不要挤**；社交矩阵 **单行可扫完** 为理想宽度 |

## 第五轮：落地顺序（先背景，后框架）

与 `00-Vision` 第五节互补，**本阶段强调「纵向深度」与「新模块」**：

1. **定令牌**：在 `globals.css` 增加 `--depth-*` 与（可选）`--depth-t`，文档与代码 **同名**。  
2. **定主容器**：主内容区单一 wrapper，背景渐变或 `color-mix` **只作用于此层**，不与 WebGL 抢解释权重。  
3. **定区块壳**：Social / Founder / Community **各占一节**，每节 **12 列栅格 + 占位数据**。  
4. **接真实数据**：外链、iframe、二维码资源、CMS/JSON 任选。  
5. **Scroll 绑定深度**：`ScrollTrigger` 驱动 `--depth-t`，与现有 wave 相机 scrub **同一套 reduced-motion 门控**。
