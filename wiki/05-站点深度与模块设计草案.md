## 第一轮：纵向隐喻与色彩系统（海面 → 海底）

### 1.1 叙事

- **浪前（近海面）**：空气与光更足，背景偏 **浅蓝 / 薄青**（仍属深色 UI，但不是纯 `#131313` 一块死黑）。
- **下潜**：随页面 **向下滚动**，背景在 **色相与明度上连续下沉**（可辅以轻微饱和度衰减），直到 **深海区**：**深蓝近黑**（与当前 `--background` / `--brand-navy` 家族衔接）。
- **寓意**：从「浪前车库」的开放入口，进入证据、人物与社群的 **水压递增区**；信息密度可随深度略升，但 **对比度与可读性** 必须全程合格（Harmless Engineering）。

### 1.2 工程落点（后续开发时遵守）

| 手段 | 用途 | 风险 |
|------|------|------|
| **CSS 变量链** | 定义 `--depth-surface`（浅）、`--depth-mid`、`--depth-abyss`（深），按 **区块或滚动进度** 插值 | 与 **全局 WebGL 底床** 叠色时需测合成，避免发灰或发粉 |
| **`color-mix()` / 长渐变** | `body` 或主内容包装层 **极缓** 的 `linear-gradient(180deg, …)` | 须与 `GlowRiver`、首屏网格 **同读一套深度令牌**，避免两套叙事打架 |
| **ScrollTrigger scrub** | 将 `--depth-t`（0→1）绑定滚动，驱动上述变量 | 与现有 `--wave-*`、相机变量独立命名，避免 GSAP 串改；**写入 `--depth-t` 须为有限数且钳制在 `[0,1]`**（见 `motion/register-global-depth-scrub.ts`、`wiki/04` §9），否则 **`color-mix`** 链可能失效 |

### 1.3 与现有首屏的关系

- 首屏可保持 **略浅** 的「海面感」；**#founders（片场）及以下** 逐步沉入深蓝。  
- **首屏 WebGL** 形态以代码为准（平滑海面片 + Bloom 等）；色彩下沉主要由 **HTML/CSS 层** 承担，WebGL 仅 **降低存在感**（已有 `--wave-opacity` 等），避免双主导。
- **首页氛围**：`app/page.tsx` 在 **`GlowRiver`** 之上叠 **`WaterVolumeFx`** 与 **`UnderwaterLightStage`**（均随 **`--ambient-mode`** 淡出）。底色为 **`sg-main-depth-paper` + `sg-main-depth-submerge`**：水下渐变限定 **首屏 118vh**，与 **`--surface-mode`** 同步，避免 Hero 底黑带（**`wiki/04` §12**）。合成过亮时优先减 **screen** / shader alpha，勿再叠独立 bridge 渐变条。

## 第二轮：官网「有多深」— 信息架构（IA）草图

以下为 **单页加长** 与 **未来子路由** 可并存的结构；深度用 **纵向区块顺序** 表达（非必须一页到底，但叙事连续）。

| 顺序（浅 → 深） | 区块（工作名） | 对应产品叙事 | 备注 |
|------------------|----------------|----------------|------|
| 0 | **Manifesto / Hook** | 浪前、品牌重击 | 已实现骨架 + 底床 |
| — | **The Proof（证据列表）** | （**已从首页移除**；若需「证据链」叙事，可改为子路由或并入 Founders / 运营位） | 原 `lib/proof-streams` + `#proof` 已删 |
| 1 | **Founder Media（创业者采访）** | 人物与故事 | 视频 B 站 + 文章外链微信 |
| 2 | **Social Matrix（社交矩阵）** | 一键抵达各阵地 | 见第三节 |
| 3 | **Community & Contact（社群与联系）** | 入群、找人 | 与现有 **The Call** 合并或上下级；含助手二维码 + 其它渠道 |

**「有多大」的实用定义**：

- **MVP 首页纵向**：约 **4～6 屏有效内容高度**（视文案与卡片数量），避免为深而深。  
- **子页面**：单篇采访、单篇微信跳转说明页等 **另起路由**，不在首屏堆完全文。  
- **深度令牌**：全站建议 **0～1 单一进度** 映射到背景插值；子路由进入时可 **重置或继承** `depth`（实现阶段再定）。

## 第三轮：三大模块 — 需求与界面约束

### 3.1 社交媒体矩阵（Social Matrix）

- **目标**：用户 **一眼扫到** 全渠道，**一次点击** 跳转站外。  
- **形态建议**：  
  - **Linear 感**：一行或两行 **等宽卡片** / **图标 + 短标签**，`hairline` 边框、hover 仅 **边框或前景微亮**，无大块色块跳动。  
  - 渠道示例（以实际运营为准）：B 站、微信、微博、小红书、Twitter/X、LinkedIn 等。  
- **工程**：外链 `rel="noopener noreferrer"`；图标 **SVG** 或 **单色**；考虑国内加载 **不依赖外网 icon CDN**。  
- **A11y**：每个链接 **可聚焦**、`aria-label` 写明平台名。

### 3.2 创业者采访（Founder Media）

**（a）视频类**

- **内置 B 站 iframe**：使用官方 embed（`player.bilibili.com`），**懒加载**（`loading="lazy"` + 进入视口才挂载 iframe），减少首屏与滚动 TBT。  
- **版式**：16:9 容器 + `aspect-ratio`；标题 + 人物一行 meta；与 Linear 一致 **大留白 + 细分割线**。  
- **合规**：遵守 B 站外链与品牌使用规范；若需备案或隐私说明，在模块下 **一行小字**。

**（b）文章类**

- **跳转微信公众号**：卡片展示标题、摘要、日期；点击 **新开页** 到微信文章 URL（若仅有二维码则 **次选**，优先可点击 URL）。  
- **工程**：外链同 3.1；若无法直链，采用 **「复制链接」+ 二维码** 双通道。

**分类展示**：Tab 或 **两段列表**（「视频」「文章」）二选一；默认 **视频在上** 或按运营权重配置。

### 3.3 社群与联系方式（Community & Contact）

**（a）小助手二维码**

- **目标**：进入「浪前」社群。  
- **形态**：与 Linear 类似 **单卡**：左侧文案 + 右侧 **固定尺寸二维码**（`220×220` 左右），浅 `hairline` 框。  
- **工程**：图片 **Next/Image** 或静态 `public/`；提供 **简短说明**（扫码后步骤）。

**（b）联系我们**

- 与现有 **邮箱、微信复制、合作说明** 合并为 **同一深度区**，避免分散在多个「Call」变体。  
- **不**在滚动中改正文 `opacity`（项目红线）。

## 第四轮：Linear 式「高级感」— 可执行的设计语言（非照抄）

参考 [Linear](https://linear.app/) 的 **气质**（非像素级复刻）：**暗色、高信噪、极少装饰、动效克制、边框即层次**。

| 维度 | 做法 |
|------|------|
| **背景** | 深色底 + **极弱**纵向渐变或纯色阶变化；**不出现**大块高饱和装饰渐变 |
| **边框** | 统一 `hairline`；hover 时 **边框或前景** 略亮 1 级，非整卡发光 |
| **圆角** | **小圆角或直角** 二选一全站统一；避免「卡片圆角 + 巨型圆按钮」混用 |
| **字阶** | 英文标签 **全大写 + 宽字距**；中文正文 **略大行高**；标题 **流体 clamp** 已有则延续 |
| **动效** | **Scroll-linked** 为主；进入视口 **短促** `fade/slide`；禁止正文 `opacity` scrub |
| **密度** | 列表与卡片 **宁可少不要挤**；社交矩阵 **单行可扫完** 为理想宽度 |

## 第五轮：落地顺序（先背景，后框架）

与 `00-Vision` 第五节互补，**本阶段强调「纵向深度」与「新模块」**：

1. **定令牌**：在 `globals.css` 增加 `--depth-*` 与（可选）`--depth-t`，文档与代码 **同名**。  
2. **定主容器**：主内容区单一 wrapper，背景渐变或 `color-mix` **只作用于此层**，不与 WebGL 抢解释权重。  
3. **定区块壳**：Social / Founder / Community **各占一节**，每节 **12 列栅格 + 占位数据**。  
4. **接真实数据**：外链、iframe、二维码资源、CMS/JSON 任选。  
5. **Scroll 绑定深度**：`ScrollTrigger` 驱动 `--depth-t`，与现有 wave 相机 scrub **同一套 reduced-motion 门控**。

## 第六轮：高级动效与层次叙事（Scroll-as-Story）

> **目标**：用滚动讲「不断下潜、层次递进」的故事；**动感**来自 **位移动移、裁切、视差与 pin 节奏**，而不是满屏乱闪。  
> **红线**（全站）：与 `02-视觉与动效系统.md`、`04` 一致 — **禁止**对正文节点做 **滚动 scrub 的 `opacity` / `autoAlpha`**；`prefers-reduced-motion: reduce` 下改为 **静态排版或极短一次性** 过渡。

### 6.1 动效分层（避免「处处都在动」）

| 层级 | 触发 | 典型手法 | 备注 |
|------|------|----------|------|
| **L0 基底** | 首屏 + 纵向深度 | WebGL、`--depth-t`、Glow River | 已有；勿再叠第三套无关节奏 |
| **L1 区块入场** | 进入视口一次 | `from` y/clip-path，`toggleActions: "play none none reverse"` | 每个区块 **只做一次**，避免回程重播造成晕 |
| **L2 滚动编排** | 区块内长滚动 | `pin` + `scrub` 的 **transform / clip** | **访谈叠层**、社交展开等放这一层 |
| **L3 微交互** | hover / focus | `transition` 150–220ms | 边框/前景微亮，非整卡弹跳 |

**「重要元素」定义**：区标题、主 CTA、社交矩阵整块、访谈当前卡、社群二维码卡 —— **优先配 L1/L2**；次要链、脚注只做 L3 或静态。

---

### 6.2 社交媒体矩阵 — 「展开」聚集注意力

**产品意图**：用户滚到该区域时，从 **收束状态** 过渡到 **全渠道展开**，形成一次 **记忆锚点**。

**推荐方案 A（首选，易控性能）**：**ScrollTrigger scrub + `clip-path` + stagger**

- **初始态**：整块容器 `clip-path: inset(0 12% 0 12%)` 或 `polygon` 等效「左右略收」；内部卡片 `scale(0.98)`、`opacity` **仅用于入场首帧**（非 scrub 绑滚动），或完全不用 opacity、只靠裁切 + `translateY(10px)`。
- **滚动过程**：用户向下 scrub，`clip-path` 放开至全宽；子项 **stagger** `y: 8 → 0`（`ease: none` 跟 scrub）。  
- **收束标题行**：区标题可先 **pin 极短距离**（如 `0.15` 视窗高度），再开始展开网格，形成 **「标题停一下 → 渠道炸开」** 的节奏。

**推荐方案 B（更强戏剧感，成本略高）**：**「卷轴」展开**

- 上层一块 **纯色/渐变蒙片**（与深度背景连续），`translateY` 随 scrub 上移揭开下方图标行；揭开过程 **不露白闪**（蒙片色须与 `--depth-mid` 一致）。

**避免**：用 `height: 0 → auto` 驱动主布局（重排昂贵）；避免 **无限循环** 的 attention 动画（违反 Harmless）。

**降级**：`reduced-motion` 下 **跳过 scrub**，展开态默认 **已完全展开** 或仅用 **50ms 内** 的 opacity 到 1。

---

### 6.3 创业者访谈 — 「当前后撤，引出下一位」

**产品意图**：同一视域内，**当前访谈主体**随滚动 **向后（沿 -Z 或等效为缩小 + 上移）退场**，下一张 **从深处滑入前景**，形成 **卡组 / 深度栈**。

**推荐实现范式：Sticky Stack（粘性叠卡）**

- **结构**：`#founders` 内 **N 个 panel**，每个 `min-height: 85vh`～`100vh`（按内容调）；外层 `position: relative`。  
- **每个 panel**：
  - `ScrollTrigger.create({ trigger: panel, start: "top top", end: "+=130%", pin: true, pinSpacing: true, scrub: 0.45 })`（数值实现时校准）。  
  - **panel 内层**（实际动的是 wrapper，不是正文叶节点）：`scrub` 驱动 `transform: translate3d(0, y%, 0) scale(s)`：  
    - 前 1/3 进度：**当前** 从 `scale(1)` → `scale(0.88)`，`y` 从 `0` → `-6%`（「向后拉」）；  
    - 中 1/3：**下一张** 从 `y: 8%`、`scale(0.94)` → `0 / 1`；  
    - 后 1/3：可接 **细分割线** 或 meta 行入场（仍只用 `y` / `clip-path`）。  
- **透视（可选）**：父级 `perspective: 1200px` + 子级 `translateZ(-40px)` 强化「后撤」——**移动端慎用**，优先 `scale + translateY` 保证帧率。

**与 B 站 iframe 的配合**

- **当前 pinned 卡** 内 iframe **允许播放**；**离开 pin 区** 时 `postMessage` 暂停或卸载 iframe（实现阶段再定），避免后台视频吃 CPU。

**备选轻量范式**：无 pin，仅用 **视差**：当前 `y` 慢、下一 `y` 快（`scrub` 双不同 speed），高级感略弱但 **实现与维护更简单**。

### 6.4 其它模块的「高级感」最低配

| 模块 | 建议动效 |
|------|----------|
| **证据/内容列表（子页或未来区块）** | 行级 **stagger from**（范式可复用）；hover **仅颜色/左边线**；首页 **The Proof 区已移除** |
| **Community 二维码卡** | 入场 **clip-path 自下而上** 揭示；hover **无 scale 弹跳** |
| **Footer** | 静态或 **极轻** 一次 `opacity`（非 scrub） |

### 6.5 工程实现清单（交付 `home-scroll-choreography` 或拆分 `home-motion-*.tsx`）

1. **所有新 ST 必须** 包在 `gsap.context()` 内，与现有编排 **同一 `useLayoutEffect` 树** 或 **子 context**，卸载时 `revert()`。  
2. **pin 数量**：访谈 N 张即 N 个 pin 区 —— **N ≤ 6** 为软上限；超出则改 **子页列表** 或 **横向滑动** 降 pin 数。  
3. **`ScrollTrigger.refresh()`**：社交/访谈 DOM 高度变化后（图片、iframe 加载）必须 **再 refresh**（沿用现有 `resize` / `fonts.ready` 逻辑）。  
4. **Lenis**：保持 `ScrollTrigger.update` 与 `scrollerProxy` 已同步，勿第二套滚动劫持。  
5. **验收**：中端机 **连续滚动无长时间掉帧**；`reduced-motion` 下 **无 pin 卡死**、内容全可读。
