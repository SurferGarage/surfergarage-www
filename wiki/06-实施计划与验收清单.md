# 06 · 实施计划与验收清单（执行到位版）

> **用途**：把 `05-站点深度与模块设计草案.md` 里的设计 **拆成可验收的工序**；每步完成再打勾，避免「边想边写」导致返工。  
> **原则**：**依赖先行 → 视觉令牌 → 静态壳 → 动效 → 真实数据 → 回归**；任一步未过验收，**不进入下一步**。

---

## 0. 全局规则（Definition of Done）

| 规则 | 说明 |
|------|------|
| **红线** | 不对正文叶节点做 **滚动 scrub 的 opacity/autoAlpha**；遵守 `02` / `04`。 |
| **动效** | 新 ScrollTrigger 全部在 **`gsap.context()`** 内；`reduced-motion` 与现编排 **同一套分支**。 |
| **性能** | 新 pin 区数量可控；访谈叠卡 **N≤6**（见 `05` 第六轮）；B 站 iframe **懒加载 + 离屏处理策略**写清再写码。 |
| **导航** | 每新增 `id` 区块，**header 锚点**与 **`scroll-mt`** 同步更新，避免 Lenis 下锚点被挡。 |
| **文档** | 代码合并后 **更新 `01`/`05` 附录映射表**（文件路径与 `data-*` 钩子名）。 |

---

## 1. 依赖顺序（不可跳步）

```text
P0 规格冻结（色值、区块 id、数据形状）
  → P1 纵向深度（CSS 变量 + 主容器 + 可选 --depth-t）
  → P2 社交矩阵（静态 UI → 展开动效）
  → P3 创业者访谈（静态卡壳 → Sticky Stack）
  → P4 社群与联系（二维码区 + 与 The Call 合并策略）
  → P5 全站回归（性能 / A11y / reduced-motion / 真机）
```

## 8. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 渐变 + WebGL + Glow **发灰** | P1 单列 PR，随时 `git revert`；先 **纯色阶** 再渐变 |
| pin 过多掉帧 | 先减 **N** 或减 **pin 时长**；再考虑关透视 |
| SmoothScroll `killAll` ST 与新增 id 冲突 | 新 ST 仍只在 **编排 context** 注册（见 `01`） |
