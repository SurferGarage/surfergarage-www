# 03. 性能与自动降级策略

## 目标

- 默认丝滑
- 弱设备自动保命
- 出现异常自动退出 WebGL，不影响主内容

## 自动分档（概念）

- `high`：高性能设备，较高 dpr 与细节
- `balanced`：主流设备，降低分辨率和演化强度
- `safe`：低性能/高风险场景，关闭 WebGL

## 当前阈值表（代码基线）

- Root 判档：
  - `lowCpu`: `hardwareConcurrency <= 4`
  - `balanced` 候选：`lowCpu` 或小屏粗指针或 `cpuThreads <= 6`
  - `safe` 条件：`prefers-reduced-motion` / `saveData` / `2g` / (`lowCpu` 且小屏粗指针)
- 冷启动校准窗口：
  - 时长：`3000ms`
  - 低帧定义：`fps < 34`
  - 高帧定义：`fps > 53`
  - 档位转换：
    - `high -> balanced`：`lowRatio > 0.32`
    - `balanced -> safe`：`lowRatio > 0.5`
    - `balanced -> high`：`highRatio > 0.82`
- 运行时逃生舱：
  - 低帧阈值：`LOW_FPS_THRESHOLD = 28`
  - 低帧累积窗口：`LOW_FPS_WINDOW_MS = 2800`
- Canvas 渲染配置：
  - `frameloop = "always"`
  - `dpr`：`high [1, 1.5]`，`balanced [1, 1.1]`
  - `powerPreference`：`high-performance` / `default`
- Scene 负载配置：
  - `grid`：`high 64`，`balanced 48`
  - `maxStepsPerFrame`：`high 4`，`balanced 2`
  - `velocityDeadzone`：`high 0.02`，`balanced 0.04`
  - `velocityBoostFactor`：`high 1.2`，`balanced 0.65`

## 初始判定因子

- `prefers-reduced-motion`
- `navigator.connection.saveData`
- `effectiveType`（弱网）
- `hardwareConcurrency`
- 屏幕/指针特征（移动端触控设备）

## 冷启动校准

- 启动后短窗口采样（约 3 秒）
- 根据低/高帧占比做二次调档
- 调档后应重置窗口，避免历史样本污染

## FPS 采样实现基线（当前）

- 监控循环基于 `requestAnimationFrame` 获取真实渲染帧
- 以约 `220ms` 时间窗聚合平均 FPS（降噪）
- 校准与逃生舱都使用该聚合 FPS，不直接使用单帧抖动值

## 运行时逃生舱（Escape Hatch）

- 若连续低帧累积超过阈值（窗口判定），触发 `onRuntimeFailure`
- 触发后关停 WebGL 层，仅保留 CSS/SVG 背景

## 推荐调参项（按优先级）

1. `dpr`（最先降）
2. `grid`（如 64 -> 48）
3. `maxStepsPerFrame`
4. 速度注入强度（`boost`）
5. WebGL `powerPreference`

## 调参策略建议

- 首选调 `dpr` 与 `maxStepsPerFrame`，副作用最可控
- 若仅移动端卡顿，优先提高 `safe` 命中条件，不要直接压低桌面档位
- 若静置也掉 `safe`，先检查 watchdog 数据源是否仍为真实帧统计

## 维护时必须避免

- 用“采样器间隔”直接当“渲染帧间隔”去算 FPS
- 监控逻辑与渲染逻辑互相放大（导致误判）
- 为追求效果强度牺牲输入响应和滚动流畅度
- 在 `safe` 兜底路径失效前就手动强关 WebGL（会损失可用设备的视觉层）

## 验收基线（建议）

- 桌面主流机：滚动期间体感稳定，无遮挡卡顿
- 手机中端机：至少不掉到“持续明显掉帧”
- `safe` 档：页面信息层完整，无视觉断层
