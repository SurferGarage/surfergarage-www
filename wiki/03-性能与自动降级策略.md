# 03. 性能与自动降级策略

## 目标

- 默认丝滑
- 背景动效在低端设备上也要平稳
- WebGL：**首屏 Hero 主 Canvas**（layout 单例）承担海面 + Bloom；**首页另有一路轻量全屏 Shader**（`WaterVolumeFx`，无 PostProcessing），须与 **视口外停帧 / reduced-motion** 策略一并验收

## WebGL（Hero）侧：已有机制

1. `prefers-reduced-motion: reduce`：**不挂载** `HeroWaveCanvas`（零 WebGL）
2. `Canvas`：`dpr` 上限 **1.5**，`antialias: false`，无 depth/stencil
3. `frameloop`：Hero **离开视口**（IntersectionObserver，含底部约 12% `rootMargin`）或 **`document.hidden`** 时为 `never`
4. 触控：`(pointer: coarse)` 时降低指针扰动累加，减少误触「炸场」
5. 滚动接近 `#proof`：通过 CSS 变量降低 `--wave-distortion` / `--wave-opacity`，减轻后半段 GPU 与视觉负载

## WebGL（首页 `WaterVolumeFx`）侧：补充机制

1. **`prefers-reduced-motion: reduce`：不挂载**（与 Hero 一致）
2. **仅首页**：由 `app/page.tsx` 引用；**无** `EffectComposer`，单 `ShaderMaterial` 全屏四边形；`dpr` 上限 **1.5**、`antialias: false`
3. **`frameloop="always"`**：当前实现**不**随 Hero 的 IO 停帧（成本低于 Hero+Bloom）；若 profiling 显示低端机首页 GPU 过高，可后续改为 **`demand`** 或与滚动 **`--depth-t`** 联动降采样
4. 每帧 `getComputedStyle` 读 `--depth-t` / `--wave-scroll-vel`：与 Hero 相同数据路径，若需优化可改为订阅同一 ref（见 `00-Vision` 数据进 GPU 路径）

## 推荐调参项（Glow / SVG，按优先级）

1. SVG/Glow 层 `opacity`
2. blur 强度（`filter: blur(...)`）
3. 动画周期（`14s/19s/22s` 等）
4. 位移振幅（`translate3d` 百分比）
5. 动画数量（是否保留 shimmer）

## 推荐调参项（Hero WebGL，按优先级）

1. `Bloom`：`intensity`、`luminanceThreshold`、`luminanceSmoothing`
2. Shader 内光带频率/宽度（`smoothstep`、`sin` 乘子）与 `uOpacity` 初值
3. `dpr` 区间（例如改为 `[1, 1.25]`）
4. `IntersectionObserver` 的 `rootMargin`（更早停帧 vs 更晚恢复）

## 调参策略建议

- Glow：首选调低振幅与 blur，再考虑删动画层；若仅移动端卡顿，优先关闭 shimmer 或延长周期
- Hero：先动 **Bloom 与 opacity/distortion 曲线**，再动 shader 内层循环复杂度
- 所有改动必须保证文字对比度稳定

## 维护时必须避免

- 为追求效果强度牺牲输入响应和滚动流畅度
- 在多个区块重复挂载重型 `EffectComposer` / 多 Canvas
- **在首页再叠加第三路**常驻全屏 WebGL（当前为 Hero + `WaterVolumeFx` 两路）；新增全屏效果优先走 CSS/SVG 或合并进现有 Shader
- 在 `useFrame` 内引入与渲染无关的重计算（当前实现以 uniform 更新为主，保持该模式）

## 验收基线（建议）

- 桌面主流机：滚动期间体感稳定，无遮挡卡顿
- 手机中端机：无明显掉帧，无亮度抽动；离开首屏后 GPU 占用应明显下降（停帧）
- 关闭动效偏好下：纯静态排版依然完整可读（含无 WebGL）
- **首页**：无 `WaterVolumeFx` / `UnderwaterLightStage` 时，仍保留 **`sg-main-depth` + `GlowRiver`**，视觉叙事成立
