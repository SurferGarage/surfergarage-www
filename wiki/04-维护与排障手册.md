# 04. 维护与排障手册

## 常见故障与处理

### 0) 控制台 `IntersectionObserver: rootMargin must be specified in pixels or percent`

现象：进入片场或视频播客时整页报错，B 站不加载。  
原因：`IntersectionObserver` 的 **`rootMargin` 不允许 `vh`/`vw`**，仅 **`px` 或 `%`**。  
处理：片场预取使用 **`lib/use-founder-panel-visible.ts`** 内 **`measurePanelPrefetch`（滚动 + `getBoundingClientRect`）**，勿写 `rootMargin: "50vh"`。见 **`wiki/09`** B 站小节。

### 1) 刷新后背景亮度先黑后浅

现象：首屏短时间内亮度突变。  
优先检查：

- 是否有延迟挂载的背景层导致“后出现”
- 是否有正文/容器 opacity 动画影响观感
- 是否存在多层背景透明度叠加导致的突变

处理原则：

- 首帧视觉必须可预测
- 能稳定就先静态，后续再逐步恢复动态

### 2) 文字偶发“抽白/闪变”

现象：正文偶发从暗白变亮白。  
优先检查：

- GSAP 是否对正文使用了 `opacity/autoAlpha` scrub
- 是否多动画叠加在同一文本节点

处理原则：

- 正文只做位移/裁切，不改透明度
- 对比度由固定颜色变量提供，不依赖动画

### 3) 页面卡顿严重

优先检查：

- Glow/SVG blur 强度是否过高
- shimmer 动画是否过快或过密
- 是否有多段动画叠加在同一区域

处理顺序：

1. 先禁用 shimmer 并降低 blur
2. 再延长动画周期、降低位移振幅
3. 必要时仅保留静态 Glow 层

### 4) Safari iOS 闪烁/撕裂

优先检查：

- `clip-path + pin` 组合是否同时作用于同层
- 是否缺少 `matchMedia` 条件隔离
- 是否存在过重滤镜叠加

### 5) 首屏 WebGL 不显示或一直空白

优先检查：

- 系统/浏览器是否开启 **`prefers-reduced-motion: reduce`**（此时故意不渲染 `HeroWaveCanvas`）
- 控制台 WebGL / shader 编译错误（驱动、扩展、内容安全策略等）
- `[data-hero-wave]` 是否在 DOM 中存在且与 `hostSelector` 一致（`home-hero.tsx` 与 `HeroWaveCanvas` 传参）

### 6) 首屏卡顿 / 手机发热

优先检查：

- 是否长时间停留在首屏且 Bloom 过强（调低 `intensity` 或提高 `luminanceThreshold`）
- Hero 是否在视口外仍跑满帧（确认 `IntersectionObserver` 与 `frameloop` 逻辑）
- Glow River 的 blur/shimmer 是否与 WebGL 叠加重负载

### 7) 滚动时 pin / scrub 错位（Founders 叠卡、Manifesto 等）

优先检查：

- 断点切换、字体加载后是否需 `ScrollTrigger.refresh()`（`home-scroll-choreography` 已接 `resize` 与 `fonts.ready`，若仍错位再查 Lenis 同步或第三方布局插入）

### 8) ScrollTrigger 全部失效、滚动动画都不动

可能原因：

- **`SmoothScroll` 已卸载 Lenis**：其 cleanup 会 `ScrollTrigger.getAll().forEach(kill)`。例如用户刚打开系统「减少动态效果」、或开发时热更新导致 Lenis effect 重跑，可能短暂清空 ST。
- **处理**：整页刷新；或确认 `prefers-reduced-motion` 与 `HomeScrollChoreography` 的 `reduced` 状态一致后，重新进入页面让编排 effect 再注册一遍。

若业务上引入第二套 ScrollTrigger，需按 `01-架构与模块说明.md` 中「Lenis 与 ScrollTrigger 生命周期」评估是否收窄 `kill` 范围。

### 9) 刷新后滚到页底：背景发灰、中间竖向青光异常

现象：`html` / `.sg-main-depth` 似失效，露出浅灰底，叠 **`WaterVolumeFx`** / **`.uwl-godrays`** 的 **screen** 混合后像一道竖向亮条。

根因（已防）：`:root` **`--depth-t`** 若被写成 **`"NaN"`** / **`"Infinity"`**（例如 **`ScrollTrigger`** 在 Lenis **`scrollerProxy`** 尚未对齐、或 **`progress`** 偶发非有限数时 **`toFixed`** 产物），**`globals.css`** 里 **`--sg-dt: clamp(0, var(--depth-t), 1)`** 与依赖 **`--sg-dt`** 的 **`color-mix`** 会在计算值阶段整条无效，背景链断裂。

根因（**GLSL**）：**`WaterVolumeFx`** 片段里曾使用 **`smoothstep(edge0, edge1, x)` 且 `edge0 > edge1`**（如 **`smoothstep(1.02, 0.03, uv.y)`**），按 GLSL 规范为**未定义行为**，部分驱动在滚到长页底部视口时会渲出**竖向尖峰/发灰**。已改为合法 **`1.0 - smoothstep(…)`** 形式，并对丁达尔锥分母 **`max(..., 0.02)`** 限幅。

根因（**叠层**）：**`footer`** 若**无实底**，`z-[3]` 仍可能让 **`mix-blend-screen`** 氛围层在页脚缝上与浅色区**错合成条**；**`page.tsx` footer** 已加 **`bg-[var(--background)]`** 兜底。

处理与约定：

- **`motion/register-global-depth-scrub.ts`**：仅通过 **`formatSafeDepthProgress`** 写入 **`--depth-t`**（有限性 + **`[0,1]`**）。
- **`underwater-light-stage.tsx`**：从 computed style 解析的 **`--depth-t`** 用于光色、丁达尔前 **`clamp(0,1)`**。
- **`water-volume-fx.tsx`**：片段中 **`smoothstep`** 须满足 **`edge0 < edge1`**；锥光分母勿趋近 **0**。
- **`app/page.tsx`**：**`footer`** 使用 **`bg-[var(--background)]`**，避免与 **`WaterVolumeFx` / `.uwl-stage`** 叠出缝。
- 若仍复现：再查 **`ScrollTrigger.refresh`** 时机（`home-scroll-choreography` 与 **`SmoothScroll`** 的 **`resize` / `fonts.ready`**）、以及是否有第三方脚本改写 **`--depth-t`**。

### 10) 生产构建 / CI 拉字体失败

现象：`next build` 报 Google Fonts 或 `@vercel/turbopack-next/internal/font` 相关错误。  
处理：保证构建机可访问 `fonts.gstatic.com`，或改为自托管字体文件并调整 `next/font` 用法（属基础设施变更，需单独 PR）。

### 11) 控制台 Hydration mismatch（`app/layout.tsx` → `<html className>`）

现象：开发环境控制台报 **「A tree hydrated but some attributes… did not match」**，diff 指向 **`RootLayout` 的 `<html className=…>`**；偶发伴随 Hero **REC · 年月** 与 Footer 构建日不一致。

常见原因（按优先级）：

1. **Lenis** 在 **`useEffect` 之后**向 `<html>` 追加 `lenis` / `lenis-smooth` 等 class（与 SSR 首帧 HTML 不同）。**约定**：`<html suppressHydrationWarning>`（见 `app/layout.tsx`）；属第三方库改 DOM，非业务 JSX 双份渲染。
2. **首帧动态时间**：`new Date()` 写在 Server/Client 边界两侧会得到不同字符串。**约定**：Hero REC 月码用 **`components/hero-rec-clock.tsx`**（挂载后再写 UTC）；构建日 **`lib/site-version.ts`** 仅用 **`NEXT_PUBLIC_BUILD_TIME`** 或固定 dev 占位，禁止模块顶层 `new Date().toISOString()`。
3. **浏览器扩展** 在 React 注水前改写 DOM（广告拦截、翻译、暗色模式插件）。用无痕窗口或禁用扩展对比。
4. **Dev 专用**：Turbopack / `next/font` 偶发 class hash 顺序抖动；生产构建若消失可忽略；持续存在则查是否双份 `layout` 或错误嵌套 `<html>`。

处理 checklist：

- [ ] `<html>` 已设 `suppressHydrationWarning`
- [ ] 不在 RSC 中直接渲染「当前时刻」；动态时钟放 Client 子组件 + `suppressHydrationWarning` 或占位符
- [ ] 不在 `html` 上同时写 `scroll-smooth` 与 Lenis（`globals.css`：`scroll-behavior: auto`，`prefers-reduced-motion` 再 smooth）

### 12) Hero 底与 Proof 顶背景断层（黑带 / 亮蓝跳变）

现象：Hero 底部（REC / Scroll / Index 一带）出现**纯黑横条**，紧接 Proof 顶又**突然变亮蓝**。

根因：

- **`sg-main-depth-submerge`** 曾用**整页高度 %** 渐变，长页在 Hero 底就 `transparent` → 只剩 `paper-1`，与上方深水色硬切。
- **`sg-surface-bridge` / `sg-proof-surface-wash`** 额外叠层与底层不同步，制造中间暗带与 Proof 顶亮斑。

现行约定（`app/globals.css` + `app/page.tsx`）：

- 底色拆为 **`sg-main-depth-paper`**（常驻）+ **`sg-main-depth-submerge`**（**`118vh` 固定高度** 渐变，`--ambient-mode` 淡出）。
- **勿**再使用整页 % 结束水下层；**勿**在 Hero/Proof 之间插独立 bridge 条。
- **`#manifesto::after`** 向下溢出渐变，盖住 WebGL 海面在 section 边的截断；Proof **`-mt-[6vh]`** 与 Hero 重叠。
- **`--surface-mode`**：`calc((var(--sg-dt) - 0.05) / 0.32)`，与滚动出水同步。

### 13) `next build` 警告：Turbopack 推断 workspace root 可能不对

现象：日志提示在 **`C:\Users\…`** 等**上级目录**发现 **`package-lock.json`**，Turbopack 把该目录当作 workspace root，与本包 **`surfergarage-www`** 不符。

处理：**`next.config.ts`** 已设置 **`turbopack.root`** 为 **`surfergarage-www`** 的绝对路径（与 `import.meta.url` 解析出的配置目录一致）。若仍警告，检查是否在错误的工作目录执行 `next build`，或清理多余的根级 lockfile（仅当确认不再需要时）。

## 发布前检查清单

- A11y：
  - `prefers-reduced-motion` 下动效全部优雅降级
- Performance：
  - 中端移动端滚动无明显连续卡顿
  - 长时间浏览无持续升温/掉帧恶化
  - 离开首屏或切到后台标签后，Hero WebGL 应处于停帧状态（`frameloop="never"`）
- Cross-browser：
  - Chrome / Safari（iOS）/ Edge 回归通过
- Stability：
  - 刷新后亮度恒定
  - 正文颜色无闪变
  - 背景层不会突然消失或突变

## Agent 协作约定

- 提交改动前，必须记录：
  - 改动目标
  - 涉及模块
  - 对性能与可读性的影响
- 任何“观感修复”都要附带“性能回归检查”
- 禁止在未知影响下大范围调整动画参数
