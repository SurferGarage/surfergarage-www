# 00. 项目总览

> **设计北极星**：产品语义、三层空间流、Shader 参数契约与路线图见 **`wiki/00-Vision-全局架构与设计主旨.md`**。本篇侧重工程现状与风险快照。

## 项目目标

SurferGarage 官网 V2 的目标不是“模板站”，而是：

- 以内容密度与网格排版为骨架（YC / Moonshot 风格）
- 以克制的高级动效为肌理（Lenis + GSAP + 低干扰背景）
- 工程上优先“稳定、可降级、可维护”

## 技术栈（当前）

- 框架：Next.js 16（App Router）+ TypeScript
- 样式：Tailwind CSS v4 + CSS Variables 设计令牌
- 滚动：Lenis（由 GSAP ticker 驱动）
- 动画：GSAP + ScrollTrigger + `gsap.context()` + `matchMedia`
- 首屏氛围（可选 GPU）：
  - `three` + `@react-three/fiber` + `@react-three/postprocessing`（全屏 Shader + Bloom）
- 全站背景（轻量）：
  - CSS/SVG：Glow River + Call 区 Orb（低频呼吸与漂移）

## 当前视觉基线

- 深色主背景恒定，避免刷新后亮度跳变
- 正文文字颜色恒定，避免滚动中“暗白/亮白抽动”
- Manifesto 首屏允许更强表现（波浪 + 跑马灯），接近 **`#social`** 时通过滚动 scrub **主动压低**波浪强度与跑马灯存在感
- Glow River / Orb 仍以低频低幅为主，不抢正文可读性

## 当前关键能力

- 首屏 WebGL **受控启用**：仅 Hero 区块；`prefers-reduced-motion: reduce` 下 **整段不挂载 Canvas**
- 视口外 / 后台标签页：`Canvas` 使用 `frameloop="never"` 暂停渲染循环，降低耗电与发热
- `prefers-reduced-motion` 与 CSS 层（含跑马灯）降级策略并存

## 环境变量（当前）

- `NEXT_PUBLIC_GSAP_DEBUG=1`
  - 开启 ScrollTrigger markers（仅调试环境）

## 当前已知风险（维护重点）

- 任何直接改正文 `opacity` 的动画都可能引发亮度不稳定观感。
- Safari/iOS 对 `clip-path + pin` 组合更敏感，需专项回归。
- Lenis 卸载路径会 **kill 文档内全部 ScrollTrigger**（见 `01-架构与模块说明.md` → Lenis 与 ST 生命周期）；新增 ST 来源时需评估是否冲突。
- 首屏 `useFrame` 内每帧读取 `getComputedStyle` 换 `--wave-*`：简单可靠；若 profiling 显示瓶颈，可改为由 ScrollTrigger 回调写 ref、帧内只读 uniform。

## 总体审查结论（工程健康度快照）

以下用于维护者快速把握「代码库现状」，与具体文件一一对应；细节排障仍以 `04` 为准。

### 架构轮廓

- **路由**：当前以首页 `app/page.tsx` 为主场景；`layout.tsx` 注入字体 + `SmoothScroll` 包裹全站。
- **Client 边界**：`SmoothScroll`、`HomeScrollChoreography`、`GlowRiver`、`HomeCall`、`HeroWaveCanvas` 为 Client；首屏文案主体可为 Server 组件树的一部分（`HomeHero` 为 Server，内嵌 Client Canvas）。
- **数据面**：无自建 API Route / Route Handler；无 `middleware`（截至当前）。

### 做得好的地方

- GSAP 使用 `gsap.context()` + `ScrollTrigger` 可调试 `id`，便于 `NEXT_PUBLIC_GSAP_DEBUG` 下定位。
- **减少动态效果** 在 Lenis、滚动编排、Hero WebGL、CSS 跑马灯等多层一致降级。
- `HomeCall` 复制微信号失败时回退 `prompt`；Toast 使用 `role="status"` + `aria-live="polite"`。

### 改进点 / 技术债（非阻塞）

- **`@react-three/drei`** 已在 `package.json` 中声明，但源码路径下暂无 import；若长期不用可考虑移除以减轻安装与审计面，若预留后续 drei 组件则保持并在本文注明。
- **占位与外链待替换**：`lib/social-channels.ts` 中 WeChat / Bilibili / X / YouTube 等仍为 `href: "#"`（Connect 内渲染为不可点信息卡）；`lib/wechat-official-feed.ts` 各卡 `href` 暂指向 **`https://mp.weixin.qq.com/` 首页**而非单篇文章，上线前替换为真实 `mp.weixin.qq.com/s/...` 与各平台主页链接。
- **CI / 构建**：生产构建会拉取 Google Fonts；离线或受限网络环境需有镜像或缓存策略（见排障）。

### 供应链与运维

- 仓库在 GitHub 上可能收到 **Dependabot 安全提示**；建议定期合并可接受的依赖升级，并与 `npm run build` / 真机回归绑定。

## 面向用户文案与术语（文本审查约定）

- **主语言**：页面 `lang="zh-CN"`；顶栏主导航、`#call` 内主要导航的 **`aria-label`** 使用**中文**，与正文一致。
- **区块命名（与 `href` 锚点一致）**：**宣言**（`#manifesto`）、**触点**（`#social`）、**片场**（`#founders`）、**联络**（`#call`）。触点区导览句与 `lib/social-channels.ts` 中「文章 / 视频与播客 / 开源」三分块对齐。
- **「记录」与「纪录」**：表「采写、记载」时用 **记录**（如 Manifesto 眉条「浪前 · 记录与建造」）；**纪录** 仅用于「纪录片」等固定搭配，避免混用。
- **英文品牌句**：**`Surfing Wave, Build the Great.`** 为站点级口号（`app/layout.tsx` 的 `metadata.description` 与 `#founders` 编辑部引言末尾一致）。语法刻意压缩为品牌节奏；若对外物料需规范英文，再单独定稿，不必与站内一句强制改成教科书句式。
- **栏目名**：**Surfing Founders 人物访谈** 为微信专栏主称谓；GitHub 卡标题 **Startup Playbook** 与外链文案一致。
- **渠道卡命名**：X 平台中文线标与 **`labelZh`** 建议写作 **「X（Twitter）」**，与 **`labelEn` `X (Twitter)`** 同步，避免「Twitter / X」混排造成用户困惑。
- **占位与外链**：`href: "#"` 或「即将更新」卡与 `wiki/04`、本文「占位与外链待替换」一致；公众号单卡 **`href`** 上线前须换为真实 `mp.weixin.qq.com/s/...`（见 `lib/wechat-official-feed.ts` 文件头注释）。

## 下一步建议（维护方向）

1. 优先保障“不卡 + 不闪 + 不跳亮度”
2. 在此基础上小步增强生命感（不改可读性）
3. 对自动分档策略持续做真机采样校准
4. 若增加第二套 ScrollTrigger 或多页 Lenis，先复盘 `smooth-scroll.tsx` 的全局 `kill` 策略
