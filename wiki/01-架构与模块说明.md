# 01. 架构与模块说明

## 顶层结构

  - `app/layout.tsx`
  - 注入全局字体变量（含 **300** 字重供光学补偿）
  - 用 `SmoothScroll` 包裹；其内 **`HeroWaveCanvas variant="global"`**（固定视口 WebGL 底床）与 **`z-[1]`** 页面根并列；内容根节点带 **`data-scroll-depth-root`**，供整页 `--depth-t` ScrollTrigger 取高
  - `metadata`：`metadataBase` 恒来自 **`getSiteUrl()`**（`lib/site-url.ts`）；`openGraph` / `twitter`（含默认图 `/brand-sg-logo.png`）、`alternates.canonical`
- `app/page.tsx`
  - 页面结构主入口（Hero / Social / **Connect→Founders 海沟** / Founders / Call）
  - 挂载 `GlowRiver`、`HomeHero`、`HomeSocial`、**全宽 `data-social-founders-trench`（`SOCIAL_FOUNDERS_TRENCH_MIN_H`，与叠卡呼吸带同量级）**、`HomeFounders`、`HomeCall`、`HomeScrollChoreography`
  - **刻意不做**：全页 SVG `feTurbulence` 胶片噪点层（易呈大块伪影）；背景仅依赖 `sg-main-depth` + 既有光效栈
  - 顶栏 `nav` 锚点：`#manifesto` `#social` `#founders` `#call`；**Logo 链回 `#manifesto`**：字标仅 **Surfer / Garage**（`alt="SurferGarage logo"`），与 Manifesto 主字标 **「浪前」+ `SURFERGARAGE` 巨型英文骨牌**区分
  - **首页根容器**（`app/page.tsx` 最外层 flex 列）使用 **`sg-main-depth`**：**`:root --depth-t`（0→1）** 与 `color-mix` 驱动纵向「海面→浅青→闪电蓝→海底」渐变（见 `app/globals.css`）
  - **背景栈 z 序（仅首页 `page.tsx`）**：`z-0` **`.sg-main-depth`** 实色纵列 → **`GlowRiver`**（`z-[1]`，见组件）→ **`z-[2]`** 绝对层内 **`WaterVolumeFx`**（全屏 R3F 体积片：焦散 / 丁达尔锥 / 微粒，读 `--depth-t` / `--wave-scroll-vel`）→ **`UnderwaterLightStage`**（CSS：倒置水面高光、aperture、godrays、光球；`mix-blend-mode: screen`）→ **`main` / `footer`** `z-[3]` 内容

## 关键模块

### 1) 滚动与动画编排

- `components/smooth-scroll.tsx`
  - 初始化 Lenis，**`LenisContext.Provider`** 向子树暴露实例
  - 与 ScrollTrigger 同步（`scrollerProxy` 绑定 `document.documentElement`）
  - **卸载 Lenis 时**（例如用户启用系统级「减少动态效果」导致不创建 Lenis、或热更新/路由卸载）：会执行 `ScrollTrigger.getAll().forEach((t) => t.kill())`，即清除**当前页面内全部** ScrollTrigger 实例
  - `resize`：同步调用 `lenis.resize()` 与 `ScrollTrigger.refresh()`
- `components/wave-scroll-velocity-bridge.tsx`
  - 订阅 Lenis `scroll`，**`gsap.quickTo`** 阻尼速度 → `:root` **`--wave-scroll-vel`**，供 Hero Shader **`uScrollVel`** 读取
- `components/home-scroll-choreography.tsx`（Client）
  - 编排入口：`gsap.context` + `matchMedia` + `ScrollTrigger.refresh`（`resize` / `fonts.ready`）
  - **动效参数字典**：`lib/sg-motion-system.ts`（`SG_SCRUB` / `SG_LOAD` / `SG_REVEAL` / `SG_SOCIAL` / `SG_FOUNDER_PIN` / `SG_CLIP`），各 `register-*` 只引用常量，保证层次与手感一致
  - 具体注册拆至 `components/motion/`：`register-manifesto-scroll`、`register-hero-choreography`、`register-founders-intro`、**`register-founder-breath`**、`register-github-repo-cards`、`register-social-expand`、`register-call-reveal`、**`register-global-depth-scrub`**、`register-desktop-pins`；插件侧 `motion/gsap-register.ts`
  - **`ctx` 内注册顺序**（`reduced-motion` 未开启时，与代码一致）：**`register-global-depth-scrub`**（`id: global-depth-t`，`trigger: [data-scroll-depth-root]`，`scrub` 写 `--depth-t`）→ Manifesto 景深 → Hero → … → Founders **`data-founders-intro`** → **`register-founder-breath`（`[data-founder-breath]` 内 glow 随滚 scrub 透明度）** → … → Call；**`matchMedia (md+)`** 内：`register-desktop-pins`；`reduced-motion` 下不写 `--depth-t` 由 ST、仅置 `0`

### 2) Manifesto 首屏（Hero）

- `components/home-hero.tsx`
  - `data-hero-wave`：承载 CSS 变量 `--wave-distortion`、`--wave-opacity`（**WebGL 画布在 layout**，此处仅作控制面与 IO 观察锚点）
  - 首屏正文：无整屏渐变遮罩（避免 `oklch` 与 `transparent` 插值产生横向色带）；主内容容器用轻 **`text-shadow`** 保证字在 Shader 上的可读性
  - **12 列网格**：`data-manifesto-pin` 占 **`md:col-span-2`**（第 1–2 列）；`data-manifesto-right` 自 **`md:col-start-3`** 起（大屏可收为 `lg:col-span-8`），非对称留白
  - 主标题 `h1#hero-title`：**上「浪前」**（`--font-zh`，浅灰 `#A1A1AA`、`font-light`）+ **下 `SURFERGARAGE` 一行全大写**（`wordmark-display`：`font-weight` 700、**`-0.04em` 字距**、`clamp` 巨型字号）；**`data-hero-wordmark`** 挂在英文骨牌外层 `div`（GSAP `manifesto-wordmark` 仍缩放该块）
  - 英文说明句 **We record builders…** 使用 **`rgba(255,255,255,0.72)`**，避免品牌青小字贴渐变发糊
- `components/hero-wave-canvas.tsx`（Client）
  - **`variant="global"`**：`app/layout.tsx` 单例；**`variant="embedded"`**（可选）旧式区块内嵌
  - R3F `Canvas` + 全屏 `ShaderMaterial` + `EffectComposer` / `Bloom`
  - `IntersectionObserver` + `visibilitychange` 控制 `frameloop`（观察 `hostSelector`）
  - `(pointer: coarse)` 下减弱指针扰动；**global** 下 **`pointer-events-none`** 壳层，不做指针雕刻
  - 浪面顶点色每帧读 `:root` **`--depth-t`**，随下潜略压暗（与 `sg-main-depth` 同轨）；**无拓扑线框**，为平滑三角面 + Bloom

## 近期代码审查备忘（工程一致性）

- **`SmoothScroll` teardown**：仍执行 `ScrollTrigger.getAll().forEach(kill)`；全站 ST 须由 `HomeScrollChoreography`（或同级整页编排）独占创建，见下文「Lenis 与 ScrollTrigger 生命周期」。
- **微信展台**：`FOUNDER_WECHAT_PIN_END` 必须与 **`register-desktop-pins`** 中 `wechat_oa` 的 **`end`**、`wechat-feed-scrub-sync` 的 **`end`** 一致；横滑进度须走 **`mapWechatPinProgressToHorizontalScrub`**（导语 hold + dwell），勿再线性 `0→1` 直灌 `scrollLeft`。
- **海沟与呼吸带**：`SOCIAL_FOUNDERS_TRENCH_MIN_H === FOUNDER_BREATH_MIN_H`；改其一须评估另一处视觉是否仍对齐。

## Lenis 与 ScrollTrigger 生命周期（约定）

- **当前假设**：全站 ScrollTrigger 仅由 `HomeScrollChoreography`（及未来同级的「整页编排」模块）创建，并与 Lenis **同生共死**。`SmoothScroll` 在 teardown 时 `kill` 全部 ST 不会误伤「仍应存活」的第三方实例——因为目前没有第三方。
- **若未来引入**：另一套 ST（例如 CMS 注入的动画库、第二页面根布局），必须在 Lenis 关闭或路由切换时验证是否需将 `getAll().kill()` 改为 **按 `ScrollTrigger.getById` / 自定义命名空间 / 仅 `ctx.revert()`** 等更窄的作用域，避免静默清空他人实例。
- **`ScrollTrigger.refresh()` 重复**：`SmoothScroll` 与 `HomeScrollChoreography`（防抖 + `fonts.ready`）都会在布局变化时 refresh；属于**有意冗余**，优先正确性；若合并为单一入口，须保留「字体加载完成后再 refresh」这一条路径。

## RAF 与 GPU（首屏 + 滚动）

- Lenis 使用 **GSAP ticker** 驱动 `lenis.raf`；首屏 WebGL 在可见时使用 R3F **独立 RAF**。二者叠加在低端机上为预期成本，调优顺序见 `03-性能与自动降级策略.md`。

## 维护规则

- 所有 GSAP 动画必须放在 `gsap.context()` 内，确保可回收
- Pin 逻辑使用 `matchMedia` 按断点隔离
- 背景特效必须优先保证流畅性与可读性
- 新增 ScrollTrigger 前先读 **「Lenis 与 ScrollTrigger 生命周期」** 一节，避免与 `SmoothScroll` 的全局 `kill` 语义冲突
