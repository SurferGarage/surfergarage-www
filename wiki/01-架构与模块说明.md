# 01. 架构与模块说明

## 顶层结构

- `app/layout.tsx`
  - 注入全局字体变量
  - 用 `SmoothScroll` 包裹页面内容
- `app/page.tsx`
  - 页面结构主入口（Hero / Proof / Call）
  - 挂载 `GlowRiver`、`HomeHero`、`HomeScrollChoreography`

## 关键模块

### 1) 滚动与动画编排

- `components/smooth-scroll.tsx`
  - 初始化 Lenis
  - 与 ScrollTrigger 同步（`scrollerProxy` 绑定 `document.documentElement`）
  - **卸载 Lenis 时**（例如用户启用系统级「减少动态效果」导致不创建 Lenis、或热更新/路由卸载）：会执行 `ScrollTrigger.getAll().forEach((t) => t.kill())`，即清除**当前页面内全部** ScrollTrigger 实例
  - `resize`：同步调用 `lenis.resize()` 与 `ScrollTrigger.refresh()`
- `components/home-scroll-choreography.tsx`
  - 页面文案入场与滚动联动（只做位移/裁切）
  - 桌面端 pin 策略（manifesto/proof）
  - 接近 `#proof` 时 scrub：`[data-hero-wave]` 上的 `--wave-distortion` / `--wave-opacity`，以及 `[data-hero-marquee]` 的退场（位移 + `clip-path`）
  - `resize` 防抖与 `document.fonts.ready` 后调用 `ScrollTrigger.refresh()`，降低断点/字体加载导致的触发点漂移

### 2) Manifesto 首屏（Hero）

- `components/home-hero.tsx`
  - `data-hero-wave`：承载 CSS 变量 `--wave-distortion`、`--wave-opacity`，供 Shader 每帧读取
  - 底部 `data-hero-marquee`：全宽跑马灯（样式见 `app/globals.css` 中 `.sg-marquee-*`）
- `components/hero-wave-canvas.tsx`（Client）
  - R3F `Canvas` + 全屏 `ShaderMaterial` + `EffectComposer` / `Bloom`
  - `IntersectionObserver` + `visibilitychange` 控制 `frameloop`
  - `(pointer: coarse)` 下减弱指针扰动强度

### 3) 全站背景系统（非首屏独占）

- `components/glow-river.tsx`
  - SVG 渐变路径（主路径 + shimmer 路径）
  - 低频漂移/呼吸，营造“暗流”
- `components/home-call.tsx`
  - 右侧光球（orb + core 双层）
  - 呼吸与轻浮动动画

## 依赖关系（简化）

`layout -> SmoothScroll`  
`page -> GlowRiver + HomeHero + Proof + HomeCall + HomeScrollChoreography`

## Lenis 与 ScrollTrigger 生命周期（约定）

- **当前假设**：全站 ScrollTrigger 仅由 `HomeScrollChoreography`（及未来同级的「整页编排」模块）创建，并与 Lenis **同生共死**。`SmoothScroll` 在 teardown 时 `kill` 全部 ST 不会误伤「仍应存活」的第三方实例——因为目前没有第三方。
- **若未来引入**：另一套 ST（例如 CMS 注入的动画库、第二页面根布局），必须在 Lenis 关闭或路由切换时验证是否需将 `getAll().kill()` 改为 **按 `ScrollTrigger.getById` / 自定义命名空间 / 仅 `ctx.revert()`** 等更窄的作用域，避免静默清空他人实例。
- **`ScrollTrigger.refresh()` 重复**：`SmoothScroll` 与 `HomeScrollChoreography`（防抖 + `fonts.ready`）都会在布局变化时 refresh；属于**有意冗余**，优先正确性；若合并为单一入口，须保留「字体加载完成后再 refresh」这一条路径。

## RAF 与 GPU（首屏 + 滚动）

- Lenis 使用 **GSAP ticker** 驱动 `lenis.raf`；首屏 WebGL 在可见时使用 R3F **独立 RAF**。二者叠加在低端机上为预期成本，调优顺序见 `03-性能与自动降级策略.md`。

## 维护规则

- 所有 GSAP 动画必须放在 `gsap.context()` 内，确保可回收
- Pin 逻辑使用 `matchMedia` 按断点隔离
- 背景特效必须优先保证流畅性与可读性
- 新增 ScrollTrigger 前先读 **「Lenis 与 ScrollTrigger 生命周期」** 一节，避免与 `SmoothScroll` 的全局 `kill` 语义冲突
