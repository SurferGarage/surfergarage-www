# Video Playbook · 发布视频配方

## A. 6 秒品牌识别片

| 时间 | 画面 | 声音 |
|---:|---|---|
| 0.00–0.40 | Deep Navy，弱网格；一个 Cyan 节点出现 | 低频底噪 |
| 0.40–1.20 | 节点锁定，Signal line 穿过画面 | 单次 ping + sweep |
| 1.20–2.60 | `浪前 / SURFER GARAGE` Frame Resolve | 轻触 click |
| 2.60–4.30 | `在时代浪潮之前` + Wave Pass | 音乐基音进入 |
| 4.30–6.00 | Logo + 唯一 URL / 账号 | 干净收尾 |

用途：长视频片头、活动大屏、合作片尾。不要在短视频开头强制播放完整 6 秒。

## B. 15 秒竖屏发布

| 时间 | 任务 |
|---:|---|
| 0–1.2s | Cold open：最强一句话 / 最强画面，先给内容 |
| 1.2–3.0s | T01 发布标题：谁 / 什么 / 为什么现在 |
| 3.0–9.5s | 3 个证据镜头，每个 1.5–2.5s |
| 9.5–12.5s | T03 判断或 T04 数据 |
| 12.5–15s | T06 单一 CTA |

## C. 30 秒项目 / 栏目发布

```text
00:00 真实问题（不是 Logo）
00:02 T01 单一主张
00:05 产品 / 人物 / 现场证据 A
00:10 证据 B + Frame lock
00:15 T04 数据或对比
00:20 真实人物一句话
00:25 当前状态 / 发布时间
00:27 T06 Logo + CTA
```

主张结构：`我们发现 [问题] → 所以做了 [动作] → 现在你可以 [结果]`。

## D. 60–90 秒人物预告

1. **Cold open 0–4s**：嘉宾最不符合常识的一句话。
2. **Identity 4–9s**：T02 人物卡，只交代姓名、角色与所做的事。
3. **Tension 9–25s**：他遇到的具体问题；用现场 B-roll，不用空镜图库。
4. **Evidence 25–50s**：产品、数据、动作与一次失败。
5. **Judgment 50–72s**：一条值得留下的判断，使用 T03。
6. **Open loop 72–84s**：留下尚未解决的问题。
7. **CTA 84–90s**：完整内容入口，T06。

## 产品演示画面

- 先显示上下文，再显示鼠标动作；不要一上来就极限放大 UI。
- 每次只突出一个动作，光标停留 8 帧后再操作。
- 产品画面使用 Frame + Node 标记；不盖大块透明渐变。
- 重要结果画面至少停留 1.2 秒。

## 发布视频的 5 个镜头来源

按优先级：

1. 创业者本人在做事
2. 产品真实运行 / 手部操作
3. 现场环境与关系
4. 文档、白板、原型、失败记录
5. 品牌图形关键帧

如果前四类素材不足，不用更多图形假装“内容丰富”；缩短视频。

## 发布前检查

- 前 2 秒是否已经出现问题、人物或结果？
- 是否有至少 3 个真实证据镜头？
- 是否只保留一个主张和一个 CTA？
- 横屏、竖屏字幕安全区是否分别检查？
- 是否能截出至少 3 张独立成立的传播图？
- 音乐关闭后，画面是否仍有完整叙事？
